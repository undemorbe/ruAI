# Бот поддержки ru-chatgpt.com

Пользователь пишет боту в личку → сообщение появляется в супергруппе поддержки, в отдельной теме этого
пользователя. Сотрудник отвечает в теме → ответ приходит пользователю от имени бота, без «переслано от».

- Тема создаётся на первое сообщение: название «Имя Фамилия @username», первым сообщением — карточка
  (id, имя, username, язык, дата первого обращения). Связь пользователь ↔ тема хранится в SQLite
  (`node:sqlite`), после перезапуска бот пишет в ту же тему.
- Тему удалили вручную — на следующее сообщение пользователя бот создаст новую. Закрыли — откроет снова.
- Текст, фото, документы, голосовые, видео, кружки, аудио, GIF, стикеры; альбомы уходят одним альбомом.
  «Ответ на сообщение» сохраняется в обе стороны.
- Команды в теме пользователя: `/close` (решено и закрыть, пользователю — уведомление), `/ban`, `/unban`,
  `/info`, `/t` (шаблоны), `/help`. Текст, начинающийся с `/`, пользователю не отправляется.
- Пользователю `/start` — приветствие «Напишите вопрос — ответим здесь же» и кнопки выбора темы
  (оплата, чат, возврат, другое). Выбранная тема попадает в карточку.

### Быстрые действия (кнопки)

- **Под карточкой в теме:** «🟡 В работе», «✅ Решено, закрыть», «💬 Шаблоны», «ℹ️ Инфо», «⛔ Бан» /
  «🔓 Разбанить». Карточку с кнопками можно вызвать в любой момент командой `/info`.
- **Статус** виден значком в названии темы: 🆕 новое → 🟡 в работе → ✅ решено. Первый ответ сотрудника
  сам ставит 🟡; новое сообщение пользователя в решённое обращение снова открывает тему со значком 🆕.
  «В работе» и «Решено» отправляют пользователю короткое уведомление.
- **Шаблоны ответов:** кнопка «Шаблоны» или `/t` → меню, нажатие отправляет текст пользователю, а меню
  превращается в запись «Отправлен шаблон …». Повторное нажатие ничего не шлёт. Тексты шаблонов и список
  тем — в `src/texts.ts` (`TEMPLATES`, `CATEGORIES`); после правки — выкладка и перезапуск.

Кнопки принимаются только из лички (выбор темы) и из `SUPPORT_CHAT_ID` (действия сотрудников).
`callback_data` разбирается по белому списку, а пользователь для действия берётся из темы, где нажата
кнопка, — подменённые данные кнопки ни на кого другого не повлияют.

Защита: бот принимает команды и ответы только из `SUPPORT_CHAT_ID`, из других групп и каналов выходит сам;
сообщения ботов и служебные игнорирует. Антиспам — 20 сообщений в минуту от пользователя (сверх — одно
предупреждение и молчание), бан, предел длины текста, предел новых тем в час на всех. Отправка — через
очередь: по порядку в каждом чате, повтор по `retry_after` на 429 и паузы на 5xx. В журнале только id
пользователей, без текстов и имён.

Стек: Node 24 (запускает `.ts` напрямую), чистый Bot API через `fetch`, long polling. Зависимостей во время
работы нет; `typescript` и `@types/node` нужны только для проверки типов.

```
src/
  main.ts      запуск: конфиг, проверки, опрос, остановка по SIGTERM
  bot.ts       маршрутизация личка ↔ тема, команды, кнопки, статусы, альбомы, фильтр чатов, антиспам
  keyboards.ts инлайн-кнопки и разбор callback_data
  store.ts     SQLite: пользователи, темы, соответствие сообщений
  queue.ts     очередь отправки с повторами на 429/5xx
  poller.ts    getUpdates
  telegram.ts  клиент Bot API и типы
  checks.ts    проверка прав в супергруппе, меню команд
  limiter.ts, texts.ts, config.ts, log.ts
deploy/ruai-support-bot.service   systemd-юнит
```

## Проверка

```bash
cd support-bot && npm install && npm test && npx tsc --noEmit
```

## Настройка Telegram с нуля

### 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`, задайте имя (например,
   «Поддержка ru-chatgpt.com») и username, оканчивающийся на `bot`.
2. BotFather пришлёт токен вида `123456789:AA…`. Это пароль от бота: не пересылайте его в чатах и не
   коммитьте. Если токен утёк — `/revoke` в BotFather и новый токен в env-файл.
3. Там же по желанию: `/setdescription` и `/setuserpic`.
   Privacy mode менять не нужно: бот-администратор и так видит все сообщения группы.

### 2. Создать супергруппу поддержки с темами

1. Создайте группу (только для команды поддержки), добавьте в неё сотрудников.
2. Настройки группы → «Темы» → включить. Группа станет супергруппой-форумом.
3. Добавьте бота в группу: «Добавить участника» → username бота.
4. Сделайте бота администратором: участники → бот → «Назначить администратором» → включите
   **«Управление темами»** (остальные права не нужны). Без этого права бот не сможет создавать темы.
5. После того как бот добавлен, в BotFather: `/setjoingroups` → бот → **Disable**. Так его никто не
   добавит в посторонние группы (а если добавит — бот всё равно выйдет сам).

Все участники группы считаются сотрудниками: любой из них может отвечать и использовать команды.

### 3. Узнать SUPPORT_CHAT_ID

Это id супергруппы, начинается с `-100`. Пока бот поддержки **не запущен** (иначе он заберёт обновления
себе), напишите в группе любое сообщение, затем на своём компьютере:

```bash
read -rs BOT_TOKEN && export BOT_TOKEN
```

```bash
curl -s "https://api.telegram.org/bot$BOT_TOKEN/getUpdates" | grep -o '"chat":{"id":-100[0-9]*' | sort -u
```

```bash
unset BOT_TOKEN
```

`read -rs` спрашивает токен без вывода на экран и без записи в историю команд. Число после `"id":` —
это `SUPPORT_CHAT_ID`. Если вывод пустой — отправьте в группе ещё одно сообщение и повторите.

Другой способ: откройте группу в web.telegram.org (версия «A») — адрес будет вида
`https://web.telegram.org/a/#-1001234567890`; число после `#` и есть id.

### 4. Запустить локально (для проверки)

```bash
cd support-bot && cp .env.example .env
```

Впишите `BOT_TOKEN` и `SUPPORT_CHAT_ID` в `.env` (файл в `.gitignore`), затем:

```bash
npm run dev
```

В журнале появится `started bot="…"`. Строки `setup_warning` подскажут, если не включены темы или у бота
нет права «Управление темами». Напишите боту в личку — в группе появится тема.

## Выкладка на сервер (VPS `ruai-vps`, Ubuntu)

Нужен Node 24 из NodeSource (`/usr/bin/node`, как у сервера админки). Одновременно может работать только
один экземпляр бота с этим токеном: локальный `npm run dev` перед выкладкой остановите.

1. Скопировать код (с локальной машины, из корня репозитория):

   ```bash
   ssh ruai-vps 'install -d -m 755 /opt/ruai-support-bot'
   ```

   ```bash
   rsync -az --delete --exclude '*.test.ts' --exclude testing.ts support-bot/package.json support-bot/src ruai-vps:/opt/ruai-support-bot/
   ```

   ```bash
   scp support-bot/deploy/ruai-support-bot.service ruai-vps:/etc/systemd/system/ruai-support-bot.service
   ```

2. На сервере (`ssh ruai-vps`): системный пользователь без входа и права на код:

   ```bash
   id ruai-support-bot || useradd --system --no-create-home --home-dir /nonexistent --shell /usr/sbin/nologin ruai-support-bot
   ```

   ```bash
   chown -R root:root /opt/ruai-support-bot && chmod -R go-w /opt/ruai-support-bot
   ```

3. Секреты — их вводите сами, прямо на сервере. Файл доступен только root:

   ```bash
   install -m 600 -o root -g root /dev/null /etc/ruai-support-bot.env && nano /etc/ruai-support-bot.env
   ```

   Содержимое:

   ```
   BOT_TOKEN=123456789:AA…
   SUPPORT_CHAT_ID=-100…
   ```

   Необязательные параметры (`RATE_LIMIT_PER_MINUTE` и др.) — в `.env.example`. `DATA_DIR` задаёт юнит.

4. Запуск:

   ```bash
   systemctl daemon-reload && systemctl enable --now ruai-support-bot
   ```

   ```bash
   journalctl -u ruai-support-bot -n 50 --no-pager
   ```

   Ожидается строка `started bot="…"` и ни одного `setup_warning`.

Обновление кода: шаг 1 (rsync), затем `systemctl restart ruai-support-bot`. База
`/var/lib/ruai-support-bot/support.db` при этом сохраняется. Резервная копия — `sqlite3 .backup` или копия
файла при остановленном боте.

### Если бот не стартует

- `Конфигурация бота поддержки: …` — не задана или неверна переменная в `/etc/ruai-support-bot.env`.
- `Telegram отклонил BOT_TOKEN (401)` — токен неверный или отозван.
- `poll_error … 409` — запущен второй экземпляр с этим токеном (например, локальный `npm run dev`).
- `сеть: fetch failed` — нет доступа к api.telegram.org. Юнит пускает процесс только в сети Telegram и на
  localhost; DNS должен идти через systemd-resolved (`/etc/resolv.conf` → `127.0.0.53`, так в Ubuntu по
  умолчанию). Иначе добавьте адрес DNS-сервера в `IPAddressAllow=` юнита. Проверка с сервера:
  `curl -sI https://api.telegram.org | head -1`.
- Темы не создаются — `setup_warning` в журнале: включите темы в группе и право «Управление темами».

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Что это |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от @BotFather |
| `SUPPORT_CHAT_ID` | да | — | id супергруппы поддержки, `-100…` |
| `DATA_DIR` | нет | `/var/lib/ruai-support-bot` | каталог SQLite |
| `RATE_LIMIT_PER_MINUTE` | нет | 20 | сообщений от пользователя в минуту |
| `MAX_TEXT_LENGTH` | нет | 3000 | максимальная длина текста от пользователя |
| `NEW_TOPICS_PER_HOUR` | нет | 60 | новых тем в час на всех |
| `TELEGRAM_API_BASE` | нет | `https://api.telegram.org` | свой Bot API-сервер (http — только localhost) |
