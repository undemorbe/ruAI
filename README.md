# ChatGPT без VPN (репозиторий ruAI)

Нейросеть на русском без VPN — фронтенд: лендинг, чат и оплата.

**Стек:** Vite 8 · Vue 3.5 (`<script setup>`) · TypeScript · Pinia · Vue Router · three.js · Vitest · ESLint.

## Запуск

```bash
npm ci
cp .env.example .env
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер |
| `npm run build` | проверка типов и production-сборка в `dist/` |
| `npm run preview` | локальный просмотр сборки |
| `npm run lint` / `lint:fix` | ESLint |
| `npm run typecheck` | `vue-tsc -b` |
| `npm test` | unit-тесты (Vitest + jsdom) |
| `npm run dev:admin` | админка на моке с демо-данными: http://localhost:5193, вход `admin` / `demo` / `000000` |
| `npm run build:admin` | сборка админки в `dist-admin/` (относительные пути, работает под любым секретным путём) |

## Страницы

| Путь | Страница |
| --- | --- |
| `/` | лендинг «Слова из частиц»; `/?v=<id>` — просмотр архивного варианта |
| `/chat/:id?` | чат со стримингом ответа; `/chat?q=…` сразу отправляет вопрос |
| `/pricing` | тарифы (7 / 30 / 90 дней), переключатель «Без изображений / С фото и изображениями»; `?tier=media` открывает второй |
| `/checkout/:plan?tier=` | оформление: e-mail, способ оплаты (карта, СБП, SberPay), редирект к провайдеру |
| `/payment/result` | статус платежа (поллинг) |

### Лендинг

Основной лендинг — **«Слова из частиц»** (`src/landings/words/`), чёрно-белый: 14 000 частиц (three.js) собираются в слова, которые пишет ChatGPT; курсор раздвигает частицы, а посетитель может собрать своё слово и сразу спросить про него в чате. three.js грузится отдельным чанком.

### Архив вариантов

Прежние направления лежат в `src/landings/legacy/` и в навигации не участвуют. Посмотреть любое можно по `/?v=<id>`, внизу появится переключатель архива:

1. Сфера в предложении — 3D-сфера внутри заголовка, окно раскрывается по скроллу.
2. Две двери — минимализм, тёмные тона, только факты.
3. Живой чат — продукт отвечает прямо на первом экране.
4. Цветные главы — каждая глава своего цвета.
5. Дроп — чат, поданный как модная коллекция.
7. ЙЦУКЕН — 3D-клавиатура печатает вместе с посетителем.

## Архитектура и backend

```
src/
  api/
    types.ts            доменные типы и события стрима
    http.ts             fetch-обёртка: таймаут, Bearer-токен, ApiError, чтение SSE
    services/contracts  интерфейсы AuthService / ChatService / BillingService
    services/http.ts    REST-реализация (для будущего backend)
    mocks/              реализация в браузере (localStorage), используется сейчас
    index.ts            выбор mock или http по env
  stores/               Pinia: user, chat, billing
  pages/ components/    UI приложения
  landings/
    words/              основной лендинг
    shared/             общие секции (тарифы, FAQ, CTA, футер, фрагмент чата)
    legacy/             архив вариантов + реестр и переключатель для ?v=
  content/              тексты, тарифы, FAQ
  admin/                админка — отдельная сборка (admin/index.html + vite.admin.config.ts)
    api/                контракт, http-клиент, мок
    demo/dataset.ts     детерминированные демо-данные и расчёт отчётов
    views/ ui/          разделы и общие блоки
server/                 API админки (Node 24 + Fastify): 2FA, сессии, журнал, отчёты
deploy/                 nginx, fail2ban, systemd
```

UI работает только через контракты из `api/services/contracts.ts`. Чтобы подключить backend, задайте `VITE_API_URL` и `VITE_USE_MOCKS=false`. Ожидаемые эндпоинты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/auth/me` | текущий пользователь и подписка |
| POST | `/auth/code`, `/auth/verify` | вход по коду из e-mail |
| GET | `/chats`, `/chats/:id/messages` | история |
| POST | `/chats/messages` | отправка `{ chatId, content, images?, mode? }`; ответ — SSE-поток `ChatStreamEvent` (`chat` → `delta`/`image`… → `done` / `error`) |
| POST | `/uploads` | фото в чат (multipart, JPG/PNG/WebP/HEIC до 10 МБ) → `ImageRef`; только тариф с изображениями |
| PATCH / DELETE | `/chats/:id` | переименование / удаление |
| GET | `/billing/plans?tier=text\|media` | тарифы |
| POST | `/billing/checkout` | создание платежа `{ planId, tier, … }` → `{ paymentId, confirmationUrl }` |
| GET | `/billing/payments/:id` | статус платежа |

Данные карт фронтенд не собирает: оплата проходит на странице платёжного провайдера.

## Экономика

Два тарифа, модель выбирает сервер по тарифу подписки (`MODELS` в `src/config/app.ts`):

- **Без изображений** — `openai/gpt-oss-20b` через OpenRouter, только текст. На сайте называется «ChatGPT», без имени модели.
- **С фото и изображениями** — **GPT-5.6 Luna** (`openai/gpt-5.6-luna`) для всех сообщений, включая анализ фото; генерация и редактирование картинок — OpenRouter Image Generation (`IMAGE_MODEL_ID`). Сгенерированные изображения сохраняются в истории чата.

| Период | Без изображений | С фото и изображениями | Запросов всего | В сутки |
| --- | --- | --- | --- | --- |
| 7 дней | 388 ₽ | 788 ₽ | 500 | 100 |
| 30 дней | 988 ₽ | 1 988 ₽ | 1 500 | 200 |
| 90 дней | 1 880 ₽ | 3 880 ₽ | 4 500 | 200 |

Любой запрос — вопрос, анализ фото или генерация — это 1 запрос. Генерации дополнительно считаются отдельным счётчиком; лимит генераций за период и выключатель генерации задаются в админке. Лимиты общие для всех чатов пользователя. Источник цифр — `src/content/plans.ts`, правила запроса — `LIMITS` в `src/config/app.ts`, чистые функции — `src/lib/limits.ts`.

Пользователям технические лимиты (токены, контекст, частота) не показываются — это внутренняя защита. На витрине — только период, число запросов и возможности тарифа.

Что обязан делать backend (мок в `src/api/mocks/` повторяет это для проверки интерфейса):

- **Запрос.** До 16 000 входных и 16 000 выходных токенов. В OpenRouter уходит не больше 20 последних сообщений текущего чата; если они длиннее 16 000 токенов, старые отбрасываются. Полная история хранится в БД. Обрезанный ответ помечается `message.truncated`, пользователь пишет «Продолжи» — это новый запрос. Чатов сколько угодно.
- **Защита.** Один одновременный запрос на пользователя, не больше 5 в минуту и 50 в час. Суточный и общий лимиты считаются на сервере. Суточный сбрасывается в 00:00 по Москве, общий — после успешной оплаты нового периода.
- **Деньги.** Фактическая стоимость каждого запроса (`usage.cost` из ответа OpenRouter) пишется в БД: отдельно текст/анализ (Luna) и генерация изображений; в бюджете подписки они суммируются. У подписки есть внутренний бюджет API на все чаты; при исчерпании лимита запросов или бюджета новые запросы блокируются. Ключ OpenRouter хранится только на сервере.
- **Ошибка без результата не списывается.** Запрос резервируется при приёме и возвращается, если модель не дала ни текста, ни картинки.
- **После подписки.** История чатов сохраняется и после окончания подписки.

Отказ до начала стрима — HTTP-ошибка с телом `{ message, code, retryAfter? }`, где `code` — `LimitCode` из `src/api/types.ts` (`no_subscription`, `daily_limit`, `total_limit`, `budget`, `rate_limit`, `busy`, `too_long`, `media_required`, `generation_limit`, `generation_disabled`, `bad_image`, `upstream`). Событие `done` несёт свежие счётчики `usage`, по ним чат показывает остаток на сегодня.

В моке «обрезанный» ответ можно вызвать словом «подробно» в вопросе; тариф с изображениями — оформить на `/pricing?tier=media`.

## Админка

Отдельное приложение: свой вход (`admin/index.html`), своя сборка в `dist-admin/`, в публичном бандле его кода нет. Разделы:

| Раздел | Что показывает |
| --- | --- |
| Главная | выручка за период, регистрации, новые и активные подписки, продления, отмены, расход OpenRouter, график по дням |
| Подписки и платежи | продажи по тарифам (388/988/1 880 и 788/1 988/3 880), первые и повторные оплаты, успешные и неуспешные, возвраты, подписки, которые скоро заканчиваются |
| Аналитика API | запросы, входящие и исходящие токены, средняя стоимость запроса, общий расход, расход по статьям (текст / Luna / генерация), ошибки по кодам, топ пользователей по расходу |
| Изображения | число генераций, расход и средняя стоимость генерации, генерации по периодам; выключатель генерации и лимиты генераций по периодам |
| Пользователи | ID, e-mail, регистрация, тариф и срок, использовано и осталось запросов, генерации, сколько оплатил, фактический расход API, остаток внутреннего бюджета, последняя активность; поиск, сортировка, страницы |
| Финансы | выручка, расход API, валовая прибыль и маржа, средний чек, ARPU, возвраты, маржа по тарифам |
| Настройки | внутренний бюджет каждой подписки (₽), курс $ для пересчёта |
| Безопасность | текущая сессия и журнал входов и изменений |

Контракт — `src/admin/api/contract.ts`, сервер — `server/`. Пока к серверу не подключена боевая база, отчёты отвечают 501, а с `ADMIN_DEMO=1` — демо-данными. Чтобы подключить базу, реализуйте интерфейс `AdminRepo` (`server/src/store.ts`) поверх неё.

### Защита

| Слой | Что делает |
| --- | --- |
| Секретный путь | `/<ADMIN_PATH>/` — 43 символа base64url (256 бит), подобрать нельзя. Неверный путь отдаёт обычную страницу сайта — снаружи не видно, что админка вообще есть. Стандартные адреса (`/admin`, `/wp-admin`, `/phpmyadmin`, `/api/admin` …) — ловушки с отдельным логом |
| 2FA | пароль (scrypt, N=2¹⁷) + 6-значный TOTP из приложения-аутентификатора (RFC 6238, окно ±30 с); один код нельзя использовать дважды |
| Перебор | 5 ошибок за 15 минут с IP — блок на 15 минут; 20 ошибок за час со всех IP — вход закрыт на час; не больше двух проверок пароля одновременно; nginx: 6 попыток входа в минуту |
| fail2ban | `ruai-admin` (4 ошибки за 30 минут → бан на сутки на всех портах), `ruai-probe` (сканеры ловушек), `nginx-limit-req`, `nginx-http-auth`, `sshd`, `recidive` (повторные — на неделю) |
| Сессия | случайный токен в cookie `__Host-ruai_admin` (HttpOnly, Secure, SameSite=Strict), на сервере — только хеш; привязка к браузеру; 30 минут простоя, максимум 12 часов; новый вход закрывает старую сессию |
| CSRF | обязательный заголовок `X-Requested-With: ruai-admin` и точный `Origin` для изменений |
| Заголовки | строгий CSP без inline-скриптов и стилей, HSTS, `X-Frame-Options: DENY`, `no-store`, `noindex`; секретный путь пишется в отдельный access-лог |
| Сервер | слушает только 127.0.0.1, `X-Forwarded-For` принимает только от nginx; systemd-изоляция (`ProtectSystem=strict`, без capabilities, сеть только loopback, фильтр системных вызовов) |
| Журнал | входы, ошибки входа, блокировки, изменения настроек — в разделе «Безопасность» и `/var/lib/ruai-admin/audit.jsonl` |
| Необязательно | allowlist своих IP и basic auth перед страницей входа — закомментированы в `deploy/nginx/ruai-admin.conf.template` |

### Выкладка на сервер

Боевой сервер — VPS (Ubuntu 26.04), домен `ru-chatgpt.com` (`www` → без `www`), TLS от Let's Encrypt. Доступ — по ключу, хост `ruai-vps` в `~/.ssh/config`.

**Подготовка нового сервера** (один раз, от root):

```bash
# Node 24 из NodeSource: в Node 22 из Ubuntu нет поддержки TypeScript, сервер админки не стартует
apt install nginx fail2ban certbot rsync qrencode ufw
# ... подключить репозиторий node_24.x NodeSource, apt install nodejs
deploy/deploy.sh                                  # первая выкладка в /opt/ruai (apply упадёт — это нормально)
ssh ruai-vps 'bash /opt/ruai/deploy/server-bootstrap.sh'
ssh ruai-vps 'certbot certonly --webroot -w /var/www/letsencrypt -d ru-chatgpt.com -d www.ru-chatgpt.com --key-type ecdsa --register-unsafely-without-email --agree-tos --deploy-hook "systemctl reload nginx"'
ssh ruai-vps 'bash /opt/ruai/deploy/server-apply.sh'   # включит боевой ruai.conf
```

**Каждая выкладка** — с локальной машины:

```bash
deploy/deploy.sh
```

Скрипт гоняет lint, typecheck, тесты сайта и сервера, собирает сайт (на моках, пока нет бэкенда) и админку (с относительным base — секретный путь при сборке не нужен), копирует всё в `/opt/ruai` и запускает `server-apply.sh`: тот раскладывает сайт в `/var/www/ruai/dist`, админку — в `/var/www/ruai-admin/<ADMIN_PATH>/`, собирает nginx-сниппет из шаблона, перезапускает сервис и перезагружает nginx.

**Включение админки** (один раз; пароль вводите сами, QR для приложения-аутентификатора появится в терминале):

```bash
ssh -t ruai-vps 'cd /opt/ruai/server && node scripts/admin-setup.ts admin --origin https://ru-chatgpt.com --write /etc/ruai-admin.env'
ssh ruai-vps 'bash /opt/ruai/deploy/server-apply.sh'
```

Скрипт напечатает адрес админки — сохраните его в менеджере паролей. Без `/etc/ruai-admin.env` админка не публикуется вовсе.

Проверка фильтров: `fail2ban-regex /var/log/ruai-admin/auth.log /etc/fail2ban/filter.d/ruai-admin.conf`. Смена пути или пароля — `admin-setup.ts … --force`, затем `server-apply.sh`. Секретный путь не публикуйте в репозитории, чатах и закладках общих браузеров.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `VITE_API_URL` | пусто | адрес API; пусто — работают моки |
| `VITE_USE_MOCKS` | `true` | принудительно включить моки |
| `VITE_BASE` | `/` | базовый путь; в CI для GitHub Pages — `/<repo>/` |
| `VITE_ADMIN_BASE` | `./` | необязательный абсолютный base админки; по умолчанию сборка относительная |
| `VITE_ADMIN_MOCKS` | — | `true` — админка на моке с демо-данными (`dev:admin`) |

Сервер админки читает `/etc/ruai-admin.env`: `ADMIN_PATH`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `ADMIN_TOTP_SECRET`, `ADMIN_ORIGIN`, `ADMIN_DATA_DIR`, `ADMIN_AUTH_LOG`, `ADMIN_DEMO`, `PORT` (8787). Без обязательных значений он не стартует.

## CI/CD

- `.github/workflows/ci.yml` — на push в `main` и на pull request: lint, typecheck, тесты, сборка сайта и админки; отдельный job — проверка типов и тесты `server/`.
- `.github/workflows/deploy.yml` — на push в `main`: сборка и публикация на GitHub Pages (`404.html` — SPA-fallback).

## Браузеры и устройства

Сборка под ES2020 (Safari 14+, Chrome/Edge/Firefox 90+), autoprefixer по `.browserslistrc`. Адаптив от 320px, `svh/dvh` и safe-area для iOS, поля ввода 16px (без зума), `prefers-reduced-motion` учитывается во всех анимациях. Без WebGL 3D-варианты показывают статичную замену.

## Перед запуском в прод

- «ChatGPT» — товарный знак OpenAI. На сайте указано, что сервис независимый и не связан с OpenAI; перед запуском проверьте использование названия с юристом и правилами OpenAI.
- Отзывы в `src/content/landing.ts` — **выдуманные заглушки** для вёрстки. Замените их на реальные (с согласия авторов).
- Внутренние бюджеты подписок по умолчанию — 40 % цены (заглушка, в ТЗ суммы нет); задайте свои в админке → «Настройки». Сверьте цены OpenRouter для `gpt-oss-20b`, Luna и генерации.
- Проверьте тестовым запросом в OpenRouter идентификаторы `openai/gpt-5.6-luna` и `IMAGE_MODEL_ID` (`src/config/app.ts`) и что генерация возвращает картинку в ответе.
- Подключите `AdminRepo` сервера админки к боевой базе (до этого отчёты — 501).
- Проверьте тексты оферты, политики конфиденциальности и e-mail поддержки (`src/config/app.ts`).
